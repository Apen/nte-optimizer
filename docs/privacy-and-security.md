# Privacy and security

This document describes the behavior of the current source code. It is not a
claim that arbitrary binaries from third parties are safe. Users should obtain
releases from a trusted source and verify published checksums.

## Summary

- no telemetry or analytics;
- no project account or authentication;
- no remote optimizer API;
- no account-data upload implemented by this repository;
- passive packet capture during a user-started login window;
- administrator rights limited to the scanner helper;
- decoded data stored locally under the Windows user profile;
- no game automation, memory injection, file patching, or account modification.

## Why packet capture is used

NTE Optimizer needs the player's actual characters and equipment. The scanner
uses the Windows `pktmon` tool to record packets while the user logs in, then
decodes supported NTE records from that capture. It observes traffic; it does not
change, block, replay, or forge packets.

Packet capture may contain more traffic than the records ultimately retained by
the optimizer. For that reason, raw ETL and PCAPNG files should be treated as
sensitive temporary files.

## Administrator boundary

The desktop application runs as the current user. It starts `nte-scan.exe`
through the Windows UAC prompt because `pktmon` capture requires elevated
rights. The elevated helper is responsible only for capture, decoding,
validation, and publishing the scanner export.

The hidden PowerShell process only brokers the UAC launch and waits for the
helper. The visible scanner console belongs to `nte-scan.exe`. Closing the
desktop application signals the elevated helper to stop; the helper performs an
idempotent `pktmon stop` cleanup before exiting.

## Files written locally

The persistent user directory is:

```text
%LOCALAPPDATA%\NTE Optimizer\workspace
```

It can contain:

- `account_snapshot.json`: the latest atomically published account inventory and
  decoded state;
- `local_builds.json`: character priority and locally saved proposed builds;
- `strategy_overrides.json`: user-edited strategy settings;
- `account_overrides.json`: optional manual account corrections;
- `scan-output/`: the latest validated scanner export.

During capture, ETL and PCAPNG files are created in the scanner working
directory's `input` folder. That folder is cleared at the start of a new scan,
and successful guided scans remove their current raw capture files after the
validated JSON export is published.

## Failure behavior

Scanner exports are built in a staging directory and validated before replacing
the previous generation. The manifest is written last. The desktop application
then imports the generation into a single atomic account snapshot.

If capture, decoding, validation, or publication fails, the previous valid
account snapshot remains available. An interrupted scan may leave temporary raw
capture files until the next scan cleanup; users may remove the `input` folder
after confirming that no scan is running.

## Network behavior

The current application source has no HTTP client, WebSocket client, telemetry
SDK, analytics SDK, update checker, or upload endpoint. Its network-related code
reads a local packet capture generated by `pktmon`.

Static dependencies may have their own development-time download behavior when
contributors run Go or npm package managers. That is separate from the packaged
application at runtime.

## What the application does not do

NTE Optimizer does not:

- request or store the player's NTE password;
- automate the game interface;
- inject code into the game or emulator;
- read game process memory;
- modify game installation files;
- equip or delete items in the game;
- publish builds or account data to a remote service.

## User responsibilities

- download releases from a trusted source;
- compare the archive hash with the published SHA-256 value;
- review source changes or wait for community review when appropriate;
- avoid sharing raw captures or account snapshots publicly;
- understand that game updates can temporarily make decoded fields incomplete
  or inaccurate;
- follow the game's terms and local rules governing packet capture and
  third-party tools.

## Reporting a security issue

Before public release, the project should define a private security-reporting
channel and add a `SECURITY.md` file. Do not publish sensitive captures,
identifiers, or exploit details in a public issue.
